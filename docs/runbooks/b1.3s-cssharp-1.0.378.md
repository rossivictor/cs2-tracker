### 7. Instalar por cima, com o container parado

```bash
V=cs2-tracker_cs2-data
echo "DONO=$DONO"                                   # o do passo 5; vazio: pare
docker run --rm --pull=never --entrypoint sh "$IMG" -c 'command -v unzip' || echo "PARE  a imagem não tem unzip"
donos > "$BK/donos-pre-unzip.txt"; [ -s "$BK/donos-pre-unzip.txt" ] && { echo "PARE  donos misturados"; cat "$BK/donos-pre-unzip.txt"; } || echo "OK    tudo com dono $DONO"
```

- Precisa dar `OK tudo com dono $DONO`, como no passo 5: um arquivo de outro dono faria o
  `unzip` falhar no meio (ou deixar donos misturados) e a instalação pela metade. `PARE`, ou
  sem `unzip`: **pare** (container parado, volume intacto) e devolva ao PM com a saída; suba
  de volta pelo [Abortar](#abortar-e-voltar-na-hora).
- O `unzip` e o `sed` rodam com `--user "$DONO"`, para que o que eles criam ou trocam saia com
  o mesmo dono. Com `DONO` = `0:0` eles rodam como root: é o dono real da árvore (o container
  roda como root, `Config.User` vazio), não um atalho para pular permissão.

```bash
docker run --rm --pull=never --user "$DONO" --entrypoint unzip -v $V:/d -v "$ZIPDIR:/in:ro" "$IMG" \
  -o -q "/in/$ASSET" -d /d/game/csgo; echo "unzip=$?"                   # precisa dar 0
docker run --rm --pull=never --user "$DONO" --entrypoint sh -v $V:/d "$IMG" -c \
  'wc -c < /d/cssharp_version.txt; sed -i "s/^v1\.0\.375\$/v1.0.378/" /d/cssharp_version.txt; wc -c < /d/cssharp_version.txt; od -c /d/cssharp_version.txt; grep -qx v1.0.378 /d/cssharp_version.txt && echo "OK    cssharp_version.txt"'
docker run --rm --pull=never --user 0:0 --entrypoint sha256sum -w /d/game/csgo -v $V:/d:ro -v "$BK:/bk:ro" "$IMG" \
  -c --quiet /bk/zip-membros.sha256 && echo "OK    volume = zip"
donos > "$BK/donos-instalado.txt"; [ -s "$BK/donos-instalado.txt" ] && { echo "PARE  dono diferente de $DONO depois do unzip"; cat "$BK/donos-instalado.txt"; } || echo "OK    instalado com dono $DONO"
inventario > "$BK/configs-instalado.txt"
diff "$BK/configs-antes.txt" "$BK/configs-instalado.txt"
```

- O `sed` troca só o conteúdo e mantém o formato (com ou sem fim de linha): os dois `wc -c`
  precisam ser iguais, e o `od -c` igual ao do passo 5, com `378` no lugar de `375`.
- `OK volume = zip` prova que cada arquivo do zip está no volume como veio.
- `OK instalado com dono $DONO` prova que os arquivos novos e os sobrescritos (e o
  `cssharp_version.txt` do `sed`) saíram com o mesmo dono de antes. `PARE` aqui: não recrie,
  volte pelo [rollback](#rollback) (caminho A), que devolve os donos do snapshot.
- **Diferenças esperadas no `diff`:** `cssharp_version.txt` (`od -c` e conteúdo), o sha256 do
  `counterstrikesharp.so` e o do `gamedata.json`, e no resumo de donos só a contagem do
  `DONO` (cresce se o zip trouxe arquivo novo; nenhum outro dono aparece). As listagens do
  `dotnet/` **não** mudam (o zip não traz runtime). **Qualquer outra diferença** (`core.json`, `admins.json`,
  `configs/plugins/*`, `metamod/*.ini`, `*.vdf`): registre; se afetar MatchZy ou captura,
  volte pelo [rollback](#rollback).
- Falhou o `unzip` ou o `sha256sum -c`: a instalação pode estar pela metade. Não recrie: volte
  pelo [rollback](#rollback) (caminho A).
