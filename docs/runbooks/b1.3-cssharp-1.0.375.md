## Por que não é uma linha

- A 1.0.375 trouxe o KHook (CSSharp #1418). O `Load()` nativo recusa rodar sem ele e loga
  `CounterStrikeSharp requires Metamod with KHook (plugin API 18)` (`src/mm_plugin.cpp:85-92`,
  tag v1.0.375). O guia oficial passou a pedir Metamod "build 1467 or newer, with KHook
  support".
- Nós rodamos o Metamod `2.0.0.1411`, que é API 17. Se só a CSSharp subir, ela não carrega, e
  com ela caem o MatchZy (`matchzy_loadmatch` e `css_start` viram `Unknown command`) e a
  captura. É a mesma quebra que motivou o pin (comentário em compose:55-62).
- O inverso também falha. Todo Metamod a partir do 1459 (commit `0cc4e200`, 08/09) recusa
  plugins API 17 com `Plugin uses old SourceHook Metamod build`.
- Por isso só existem dois pares que funcionam:
  - Metamod 1411 com CSSharp até a 1.0.374;
  - Metamod 1467 ou mais novo com CSSharp 1.0.375.
- Qual Metamod fixar:
  - **`2.0.0.1469`** é o casamento exato. O commit `fa6f80e4` é o submódulo metamod-source
    da própria 375, e é o par que aparece nas issues #1443 e #1446.
  - O `2.0.0.1472` também serviria.
  - O `2.0.0.1470` e o `2.0.0.1471` **não** têm asset Linux. A imagem ignoraria esses pins
    em silêncio.
- A 1.0.374 não ajuda: não traz o fix do jogo 1.41.8.2.

## Riscos e ganhos da 1.0.375

- **#1446 (aberta em 26/09):** crash-loop por Stack overflow no ChangeTeam/SetPawn do
  primeiro bot ao iniciar o mapa, na era KHook, com Metamod 1469 e jogo 1.41.8.4. Há um relato
  só, feito num build 376 da master, e ele diz que a 1.0.374 não é afetada. **Crítico para um
  servidor só de bots.**
- **#1443 (merge em 26/09, ainda sem release):** um `Respawn` logo depois do `SwitchTeam` no
  warmup faz o jogador nascer na origem e cair para fora do mapa. A MatchZy faz exatamente
  isso quando o humano está no time errado (`Utility.cs:1947-1965`, chamado em
  `MatchZy.cs:248`). Ele morre no warmup, mas o servidor não cai.
- **O que a 375 corrige e hoje está latente na 373:**

  removido na 375.
- **Captura (Cs2TrackerEvents, compilada contra a 1.0.373):** usa só schema, eventos e
  listeners, sem assinatura nem offset do gamedata. Nas classes que ela usa, a 375 só
  adicionou membros. Deve carregar sem recompilar; o B1.2 é reforço.

## Procedimento da janela

Os comandos são para o Git Bash. No PowerShell, tire o `export MSYS_NO_PATHCONV=1`, escreva
cada comando numa linha só e troque `$VAR` por `$env:VAR` ou por variáveis do PowerShell.

### Preparação do shell

```bash
export MSYS_NO_PATHCONV=1      # o Git Bash não reescreve /d, /in, /out, /home/steam
RAIZ=/c/Users/Victor/Projetos/cs2-tracker
PY=/c/Users/Victor/Projetos/cs2-tracker/.venv/Scripts/python.exe
DATA=$(date +%F); HORA=$(date +%H%M)
BK="C:/Users/Victor/cs2-tracker-backups/$DATA/b1.3r"
mkdir -p "$BK"
IMG=$(docker inspect cs2-spike --format '{{.Image}}')   # a imagem que já está no disco
rcon() { (cd "$RAIZ" && PYTHONUTF8=1 "$PY" -c 'import sys; from config import load_env; from start_match import rcon_run; print(rcon_run("127.0.0.1", 27015, load_env()["CS2_RCONPW"], sys.argv[1]))' "$1"); }
```

- O `rcon` usa a mesma função e a mesma senha do `start_match`. A senha sai do `.env` dentro
  do processo e nunca é impressa. Nunca rode `cat .env`.
- `IMG` é o id da imagem do container atual. Com `--pull=never`, os containers descartáveis
  usam essa imagem e **nunca** baixam nada. O `tar`, o `sh` e o `sha256sum` vêm dela: o
  `metamod_setup.sh` da própria imagem usa `tar -xzf`. Se o container `cs2-spike` não
  existir, use `IMG=xbird/cs2-matchzy`: com `--pull=never`, o comando falha em vez de baixar.
- Se o shell cair no meio da janela, redefina `BK`, `HORA` e `IMG` apontando para o snapshot
  desta janela antes de continuar.

### 0. Abrir a janela

```bash
"$PY" "$RAIZ/tools/preflight.py"; echo "preflight=$?"       # precisa dar 0
mkdir -p "$RAIZ/logs/janelas" && touch "$RAIZ/logs/janelas/ABERTA"
```

- Comece o registro em `logs/janelas/<data>.md` (modelo no fim deste runbook).
- A partir daqui o preflight dá 4, e isso é o esperado. Repita-o a cada passo, e a cada 30 s
  ou menos durante as esperas. **Um 3 é motivo para abortar**, salvo no smoke (passo 10).

### 1. Estado "antes"

Se o container estiver de pé, faça o seguinte. Se não estiver, pule o RCON e tire a build do
log salvo.

```bash

```

O `--force-recreate` descarta o container antigo junto com os logs dele. Por isso o log é
salvo aqui.

### 2. Backup fora do volume

Use o `tools/backup.py` (B0.6), se ele já existir. Se não existir, só **copie**, sem abrir
nada:

```bash
cp -p "$RAIZ"/cs2_tracker.db* "$BK/"
cp -p "$RAIZ/docker/events-live/current.jsonl" "$BK/" 2>/dev/null
sha256sum "$BK"/cs2_tracker.db* "$BK"/current.jsonl > "$BK/backup.sha256" 2>/dev/null
```

O `current.jsonl` vai junto porque o plugin de captura o trunca em todo boot e em toda troca
de mapa (`Cs2TrackerEventsPlugin.cs:107-111, 134-137`). Uma partida parcial que ainda não foi
arquivada se perderia no recreate. Se o `.env` definir `CS2_TRACKER_DB_PATH`, o banco está
nesse caminho, não na raiz.


### 5. Snapshot (só leitura), imediatamente antes da troca

```bash
docker run --rm --pull=never --user 0:0 --entrypoint tar \
  -v cs2-tracker_cs2-data:/d:ro -v "$BK:/out" "$IMG" \
  --numeric-owner -czf "/out/volume-addons-$HORA.tgz" -C /d \
  cssharp_version.txt mmsource_version.txt matchzy_version.txt \

docker run --rm --pull=never --entrypoint tar -v "$BK:/in:ro" "$IMG" -tzf "/in/volume-addons-$HORA.tgz" > "$BK/volume-addons-$HORA.lista.txt"
grep -c -e '^game/csgo/addons/metamod/' -e '^game/csgo/addons/counterstrikesharp/' "$BK/volume-addons-$HORA.lista.txt"
```

- **O que entra:** `addons/` inteiro, e não só `addons/counterstrikesharp`, porque o B1.3r
  sobrescreve também `addons/metamod`. Esse tar também é o único backup da instalação manual
  dos plugins de bot que estão sob as máscaras. Os três `*_version.txt` entram porque são o

- **Como:** o volume é montado `:ro` num container descartável, e nada é escrito nele. O
  `--user 0:0` lê tudo, e o `--numeric-owner` preserva o dono (usuário `steam`) para a
  restauração.

  `docker run --rm --pull=never --entrypoint ls -v cs2-tracker_cs2-data:/d:ro "$IMG" /d` e
  refaça com o nome real. Se a imagem não tiver `tar`, pare e pergunte ao PM. **Não siga sem
  snapshot.**
- Anote no registro o nome do arquivo, o sha256 e a contagem do `grep`, que precisa ser maior
  que zero.

- **Diferenças esperadas no `diff`:** só os `*_version.txt` (`v1.0.375` e `2.0.0.1469`) e o
  hash do `gamedata.json`.
- **Qualquer outra diferença** (`core.json`, `admins.json`, `configs/plugins/*`) é
  divergência. Registre. Se ela afetar MatchZy ou captura, restaure o arquivo a partir do tar
  com o container parado, ou volte.
- **Os sha256 dos cinco arquivos montados** precisam ser iguais dentro do container e no
  checkout.

**Se só a captura não carregar** (o MatchZy carregou), o card manda o seguinte: DLL
compilado contra a 1.0.375 só se o B1.2 e o B0.7b estiverem prontos, e com o container
parado antes da troca. Se não estiverem, volte (caminho 1) e marque o B1.3r como Bloqueado.

### 10. Smoke só de bots (Q7=A), condição do B1.1 para o B1.3r

O objetivo é expor o par novo, antes da partida do Victor, às duas coisas que a 375 arrisca:
bots entrando no time (#1446) e duas trocas de mapa.

```bash
T1=$(date -u +%Y-%m-%dT%H:%M:%SZ)
rcon "sv_hibernate_when_empty 0"      # sem humano o servidor hiberna, e os bots não entram
rcon "mp_warmup_end"
#   3 a 5 min de rounds
rcon "status" > "$BK/smoke-status.txt"    # precisa haver bots nos dois times
rcon "changelevel de_inferno"         # 1ª troca de mapa
rcon "mp_warmup_end"
#   3 a 5 min de rounds
rcon "changelevel de_mirage"          # 2ª troca de mapa (o ponto do RayTrace)
#   2 a 3 min

```

- É o mínimo para o B1.3r. O procedimento completo de partida só de bots fica em
  `docs/runbooks/smoke-partida-de-bots.md` (B0.9), quando existir.
- Durante o smoke e até 10 min depois, o preflight dá 3 por causa do `current.jsonl` que o
  próprio smoke escreveu. Nesse intervalo, aborte só se o motivo impresso for processo
  (`cs2.exe`, `wizard_tui`, `watcher` ou `start_match`).
- O smoke não gera partida no banco. Sem partida carregada na MatchZy não há "MAP ENDED" para
  o watcher, e a próxima troca de mapa trunca o `current.jsonl`.

## Abortar e voltar na hora

Volte (caminho 1, e caminho 2 se preciso) se acontecer qualquer um destes:

- falta qualquer uma das duas linhas `complete`, o que indica par descasado;
- a CSSharp não carrega (`requires Metamod with KHook`, `Loaded 0 plugins`, ou ausência no
  `meta list`);
- MatchZy ou captura ficam fora do `css_plugins list`. Para a captura sozinha, vale a regra
  do passo 9;
- aparece `Stack overflow` ou `Segmentation fault` quando os bots entram (#1446), ou há
  crash-loop;
- o boot passa de 15 min (descontado o download do jogo);
- o Victor abre o jogo ou a TUI (preflight 3 por processo), ou a janela passa de 45 min;
- na partida dele, depois da janela, há overflow após `SIGNONSTATE_FULL` + 60 s ou segfault.

Se o abort vier **antes do passo 6**, nada mudou no checkout nem no volume. Basta subir o
container de volta com `docker start cs2-spike`, e só se ele estava de pé no início.
