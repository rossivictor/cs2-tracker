## Por que não é uma linha

- A 1.0.375 trouxe o KHook (CSSharp #1418). O `Load()` nativo recusa rodar sem ele e loga
  `CounterStrikeSharp requires Metamod with KHook (plugin API 18)` (`src/mm_plugin.cpp:85-92`,
  tag v1.0.375). O guia oficial passou a pedir Metamod "build 1467 or newer, with KHook
  support".
- Nós rodamos o Metamod `2.0.0.1411`, que é API 17. Se só a CSSharp subir, ela não carrega, e
  com ela caem o MatchZy (`matchzy_loadmatch` e `css_start` viram `Unknown command`) e a
  captura. É a mesma quebra que motivou o pin (comentário em compose:55-62).
- O inverso também falha. Todo Metamod a partir do 1459 (commit `0cc4e200`, 08/09) recusa
  plugins API 17 com `Plugin uses old SourceHook Metamod build`.
- Por isso só existem dois pares que funcionam:
  - Metamod 1411 com CSSharp até a 1.0.374;
  - Metamod 1467 ou mais novo com CSSharp 1.0.375.
- Qual Metamod fixar:
  - **`2.0.0.1469`** é o casamento exato. O commit `fa6f80e4` é o submódulo metamod-source
    da própria 375, e é o par que aparece nas issues #1443 e #1446.
  - O `2.0.0.1472` também serviria.
  - O `2.0.0.1470` e o `2.0.0.1471` **não** têm asset Linux. A imagem ignoraria esses pins
    em silêncio.
- A 1.0.374 não ajuda: não traz o fix do jogo 1.41.8.2.

## Procedimento da janela

Os comandos são **somente para o Git Bash**. O PowerShell 5.1 não tem `&&` nem `||`, nem
`$'\r'`, `$(date +%F)`, `head`, `grep`, `sha256sum` ou as funções abaixo, e o `>` dele grava
UTF-16, que o `grep` dos passos 9 e 10 não casa. O único bloco PowerShell válido é a checagem
manual da pré-condição 3.

**Se o B0.7b já estiver na main**, use o `tools/jogavel.py` (`stop`, `snapshot`,
`recreate`, `rcon` e `restaurar`) no lugar dos comandos crus de `docker` e `docker compose`:
o hook do B0.7b bloqueia docker cru fora dele. A ordem, as conferências e os critérios
continuam os deste runbook.

### Preparação do shell

```bash
export MSYS_NO_PATHCONV=1      # o Git Bash não reescreve /d, /in, /out, /home/steam
RAIZ=C:/Users/Victor/Projetos/cs2-tracker
PY=C:/Users/Victor/Projetos/cs2-tracker/.venv/Scripts/python.exe
DATA=$(date +%F); HORA=$(date +%H%M)
BK="C:/Users/Victor/cs2-tracker-backups/$DATA/b1.3r"
mkdir -p "$BK"
IMG=$(docker inspect cs2-spike --format '{{.Image}}')   # a imagem que já está no disco
rcon() { (cd "$RAIZ" && PYTHONUTF8=1 "$PY" -c 'import sys; from config import load_env; from start_match import rcon_run; print(rcon_run("127.0.0.1", 27015, load_env()["CS2_RCONPW"], sys.argv[1]))' "$1"); }
inventario() {   # versões, runtime .NET, binários do Metamod e hashes das configs (volume :ro)
  docker run --rm --pull=never --user 0:0 --entrypoint sh -v cs2-tracker_cs2-data:/d:ro "$IMG" -c '
    cd /d && head -n 5 cssharp_version.txt mmsource_version.txt matchzy_version.txt
    cd /d/game/csgo/addons || exit 1
    for p in counterstrikesharp/dotnet/shared/Microsoft.NETCore.App counterstrikesharp/dotnet/host/fxr metamod/bin/linuxsteamrt64; do echo "== ls $p"; ls "$p"; done
    sha256sum *.vdf metamod/*.ini metamod/*.vdf
    cd counterstrikesharp
    for f in configs/*.json configs/plugins/*/*.json gamedata/gamedata.json; do
      case "$f" in *.example.json) ;; *) sha256sum "$f" ;; esac
    done' 2>&1
}
prontos() { docker logs cs2-spike 2>&1 | grep -cF '[Cs2TrackerEvents] Pronto'; }
esperar_pronto() {   # espera uma linha "Pronto" além das $1 que já havia (até 3 min)
  for i in $(seq 36); do [ "$(prontos)" -gt "$1" ] && { echo "OK    Pronto novo"; return 0; }; sleep 5; done
  echo "FALTA Pronto novo em 3 min"; return 1
}
{ printf 'BK=%s\nHORA=%s\nIMG=%s\n' "$BK" "$HORA" "$IMG"; declare -f rcon inventario prontos esperar_pronto; } > "$BK/janela.vars"
```

- **Caminhos no formato Windows, com barras (`C:/...`), nunca `/c/...`.** Com o
  `MSYS_NO_PATHCONV=1`, o Git Bash não converte nada. O `git` e o `python.exe` são programas
  nativos e recebem o `/c/Users/...` literalmente, e aí falham (testado nesta máquina:
  `can't open file 'C:\\c\\Users\\...'` e `fatal: cannot change to '/c/Users/...'`). O
  `cd`, o `cp`, o `grep` e o `sha256sum` do Git Bash aceitam as duas formas. Sem o export, o
  Git Bash reescreve `-C /d` para `D:/` e `/in/...` para `C:/Program Files/Git/in/...`, e os
  containers descartáveis quebram.
- O `rcon` usa a mesma função e a mesma senha do `start_match`. A senha sai do `.env` dentro
  do processo e nunca é impressa. Nunca rode `cat .env`.
- `IMG` é o id da imagem do container atual. Com `--pull=never`, os containers descartáveis
  usam essa imagem e **nunca** baixam nada. O `tar`, o `sh` e o `sha256sum` vêm dela: o
  `metamod_setup.sh` da própria imagem usa `tar -xzf`. Se o container `cs2-spike` não
  existir, use `IMG=$(docker image inspect xbird/cs2-matchzy --format '{{.Id}}')`: sem a
  imagem no disco, o comando falha em vez de baixar.
- O `inventario` deixa de fora os `*.example.json`, que o zip sobrescreve de propósito. As
  listagens do `dotnet/` e do `metamod/bin/linuxsteamrt64` existem para achar órfãos: uma
  pasta de versão do .NET ou de `host/fxr` que a 375 deixe para trás é escolhida pelo
  roll-forward de patch mesmo depois de voltar para a 373.
- O `janela.vars` guarda `BK`, `HORA`, `IMG` e as funções. **Se o shell cair no meio da
  janela**, abra outro e rode as três primeiras linhas do bloco (export, `RAIZ` e `PY`) e
  `. "C:/Users/Victor/cs2-tracker-backups/<data da janela>/b1.3r/janela.vars"`. Não rode o
  bloco inteiro de novo: ele troca a `HORA` e sobrescreve o `janela.vars`.



- **Espere o `Pronto` novo antes do `mp_warmup_end`.** Pela RCON, durante o load do mapa, o

  carregado. Se o `esperar_pronto` der `FALTA`, a troca de mapa não terminou em 3 min: é
  motivo para voltar.
- O log do smoke é lido pela contagem de linhas `N`, e não por `--since`, pelo mesmo motivo do

- É o mínimo para o B1.3r. O procedimento completo de partida só de bots fica em

- O preflight dá 3 durante todo o smoke, por causa do `current.jsonl` (regra do passo 0).
- O smoke não gera partida no banco. Sem partida carregada na MatchZy não há "MAP ENDED" para
  o watcher. O resíduo que ele deixa no `current.jsonl` e na contagem de rounds é zerado pelo

## Abortar e voltar na hora

Volte (caminho 1, e caminho 2 se preciso) se acontecer qualquer um destes:

- falta qualquer uma das duas linhas `complete`, o que indica par descasado;
- a CSSharp não carrega (`requires Metamod with KHook`, `Loaded 0 plugins`, ou ausência no
  `meta list`);
- MatchZy ou captura ficam fora do `css_plugins list`. Para a captura sozinha, vale a regra
  do passo 9;
- aparece `Stack overflow` ou `Segmentation fault` quando os bots entram (#1446), ou há
  crash-loop;
- o boot passa de 15 min (descontado o download do jogo), ou uma troca de mapa do smoke não
  dá `Pronto` novo em 3 min;
- o volume ou os mounts mudaram no recreate (passo 7);
- o Victor abre o jogo ou a TUI (preflight 3 **por processo**), ou a janela passa de 45 min;
- na partida dele, depois da janela, há overflow após `SIGNONSTATE_FULL` + 60 s ou segfault.

Conforme o ponto do abort:

- **Antes do merge do passo 3:** nada mudou no checkout nem no volume. Basta subir o container
  de volta com `docker start cs2-spike`, e só se ele estava de pé no início.
- **Depois do merge do passo 3 e antes do recreate do passo 7:** o volume não mudou e o
  container antigo ainda tem a config antiga. Salve a evidência (primeiro bloco do
  rollback), rode o comando 1 do caminho 1, confira o `grep -n FIXED_VERSION` (1411 e
  v1.0.373) e suba o mesmo container com `docker start cs2-spike`, sem recreate e sem
  download. O checkout fica na tag até o candidato ser retomado ou revertido (ver
  [Depois de qualquer volta](#depois-de-qualquer-volta)).
- **Do passo 7 em diante:** rollback abaixo.
